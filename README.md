# Мессенджер

Чаты в реальном времени, голосовые, фото, аудиозвонки (WebRTC), поиск по нику, аватар, несколько аккаунтов.

## Запуск локально
    npm install
    npm start        # http://localhost:3000

## Деплой на Render
1. Залей все файлы в репозиторий GitHub.
2. Render → New → Web Service → выбери репозиторий.
3. Build Command: `npm install`, Start Command: `npm start` (или просто используй render.yaml).
4. Нажми Deploy. Готово — сайт работает по HTTPS (нужен для микрофона).

## Важно
- Данные хранятся в папке `data/`. На бесплатном Render диск сбрасывается при перезапуске.
  Для постоянного хранения подключи Render Disk (платно) и задай переменную `DATA_DIR` = путь диска.
- Звонки используют STUN. В сложных сетях (мобильный интернет, строгие NAT) нужен TURN-сервер:
  добавь его в массив `ICE` в `public/index.html`.

## Почему пропадают аккаунты на Render
На бесплатном тарифе Render сервис «засыпает» после ~15 минут без запросов и просыпается с чистым диском,
поэтому `data/db.json` (пользователи, токены, сообщения) пропадает. Что делать:
- Подключить Render Disk (платно) и задать `DATA_DIR` = путь диска — данные сохранятся навсегда.
- Либо хотя бы не давать сервису засыпать: бесплатный UptimeRobot, пингующий `https://твой-сайт/health` каждые 5 минут.
  (Это не спасёт при редеплое/перезапуске — для надёжности нужен диск или внешняя БД.)

## Администратор
При запуске сервер создаёт аккаунт администратора: ник `parus`, имя `Parus`, пароль `asdfghjkl` (старый аккаунт `lcg`, если он был, автоматически становится `parus` — чаты сохраняются).
**Если репозиторий публичный — пароль виден всем!** Задай на Render переменную окружения `ADMIN_PASS` со своим паролем
(и при желании `ADMIN_NICK`, `ADMIN_NAME`) — тогда значения из кода не используются.
Админ может: банить/разбанивать пользователей (профиль пользователя → «Забанить», или Профиль → «Админ-панель»),
отправлять файлы любого размера и включать «Технические работы» для всех остальных.

## Чтобы аккаунты не пропадали при перезапуске Render (резервная копия в GitHub)
Сервер сам сохраняет всю базу (пользователи, токены, чаты, сообщения) одним JSON-файлом `messenger-db.json`
в отдельный репозиторий GitHub и при старте восстанавливает её оттуда.
1. Создай **приватный** репозиторий, например `messenger-data` (с галочкой «Add a README»). Не используй репозиторий самого сайта:
   каждый коммит в него запускал бы новый деплой на Render.
2. GitHub → Settings → Developer settings → Fine-grained tokens → новый токен: доступ только к `messenger-data`,
   права **Contents: Read and write**.
3. На Render → Environment добавь: `GITHUB_TOKEN` = токен, `GITHUB_REPO` = `твой-логин/messenger-data`
   (необязательно: `GITHUB_BRANCH`, `GITHUB_PATH`). Нажми Save — сервис перезапустится.
4. В приложении: Профиль → Админ-панель → «Копия базы в GitHub» — проверка. В логах Render будет строка `GitHub backup restored`.
Копия содержит хеши паролей и токены — репозиторий обязательно приватный. Загруженные файлы и аватарки в копию не входят
(аватарки приложение восстанавливает само из копии на устройстве).

## Аватарки и пароли в резервной копии
- Аватарки (пользователей и групп) копируются в тот же приватный репозиторий в папку `avatars/` и сами восстанавливаются при старте сервера.
- Пароли хранятся в базе в зашифрованном виде (AES-256-GCM), главный админ видит их в карточке пользователя. Задай на Render свой секретный `PASS_KEY` (любая длинная строка), иначе ключ строится из `ADMIN_PASS`.

## Уведомления, звук, приватные аккаунты
- Звук нового сообщения и всплывающие уведомления (когда вкладка не в фокусе) включаются/выключаются в Профиле → «Уведомления». Браузер один раз попросит разрешение. Уведомления приходят, пока вкладка/приложение открыты (даже в фоне); если сайт полностью закрыт, нужен push-сервер — он здесь не используется.
- При входящем звонке играет мелодия и показывается уведомление.
- Приватный аккаунт: Профиль → «Сделать аккаунт приватным». Находится только по коду: «＋» в чатах → «Найти приватного пользователя».

## Звонки и трансляция экрана через разные сети (TURN)
Если у собеседников разные сети/роутеры, прямое соединение часто невозможно — трансляция показывает чёрный экран, а звонок не соединяется.
Нужен TURN-сервер. Бесплатный вариант — metered.ca: создайте приложение, возьмите домен (вида `имя.metered.live`) и API-ключ,
затем на Render → Environment добавьте `METERED_DOMAIN` и `METERED_KEY`. Либо свой TURN: `TURN_URLS` (через запятую),
`TURN_USERNAME`, `TURN_CREDENTIAL`. Сервер сам выдаёт клиентам актуальные ключи (`/api/ice`).

## Стикеры
Файлы стикеров копируются в приватный репозиторий с базой (папка `avatars/`) так же, как аватарки, и восстанавливаются при старте.
